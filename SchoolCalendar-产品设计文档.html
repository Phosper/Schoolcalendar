1. 产品概述

1.1 产品定位

SchoolCalendar 是一款面向大学生的 HarmonyOS 原生课程表应用。应用内提供简洁高效的课表编辑与浏览体验；产品的差异化竞争力集中于桌面卡片体系——让学生不解锁手机、不打开应用，在桌面上一眼看到"接下来最近的一节课是什么、在哪里、还有多久"，并通过预设主题包实现应用与全部桌面卡片的同步换肤。

一句话定位：把课表放回桌面，把当下放进焦点。

1.2 目标用户

维度描述
核心人群中国大陆在校大学生（本科/高职），拥有 HarmonyOS 手机
场景特征每周 10-40 门次课程；作息时间因校而异；普遍存在单双周课程
核心诉求快速录入课表 → 桌面常看课表 → 课前快速决策（去哪、还来得及吗）
设备环境手机为主力（桌面卡片高频使用），部分用户有平板/折叠屏

1.3 核心价值主张

  1. 聚焦当下：桌面卡片直接回答"下一节课是什么"，而非让用户在完整周课表里自行查找。
  2. 分钟级实时：倒计时随分钟自动更新、下课后高亮自动迁移——基于鸿蒙 TextClock 卡片能力，多数竞品做不到。
  3. 个性表达：8-10 套预设主题包，应用与桌面卡片一体化换肤，补齐竞品普遍缺失的主题自定义。
  4. 系统级整合：课表一键同步系统日历，由系统日历提供课前提醒，应用无需后台常驻。

1.4 竞品差异化分析

竞品痛点（用户原述）：市面课程表应用的桌面卡片"基本上都是仅显示一份完整的本周课程信息，无法直观看到今日、明日或接下来最近的一节课是什么，且缺乏主题自定义的能力"。

能力维度典型竞品桌面卡片SchoolCalendar
信息形态仅完整周课表缩略下一节课 / 今日课程 / 完整周课表 三类卡片
时间感知静态快照，不随时间推进分钟级自治：倒计时更新、下课自动切换高亮、晚间自动前瞻明日
今日/明日视角无（需用户自行在周课表中定位）今日课程卡片默认聚焦今日，晚间自动切换明日视角
主题自定义无或仅应用内换肤应用 + 全部卡片同步换肤，8-10 套预设主题包
刷新智能性依赖打开应用触发更新三层刷新体系（主动 ≤5s / 定点对齐作息 / 分钟级自治）
系统整合应用内通知提醒（需后台）系统日历同步 + 系统级课前提醒（零后台）
差异化护城河：分钟级卡片自治能力依托鸿蒙 TextClock.onDateChange（API 11+ 卡片内可用）+ 卡片数据自治架构（详见 4.4），该组合在当前竞品中未见实现，构成体验代差。

3. 基础课表功能设计

基础功能的目标是"好用简洁"：录入快、看着清、改着顺。本章覆盖 US1/US2，对应需求 FR-001~FR-005、FR-016。

3.1 课程数据模型

属性类型/取值必填说明
课程名文本，1-20 字✅如"高等数学 A(下)"
教师文本—如"王老师"
地点文本—如"教三-201"
星期1-7✅周一至周日
节次起止区间（如第 3-4 节）✅连续多节合并为跨节色块
周次模式全周 / 单周 / 双周 / 自定义✅自定义支持任意周次组合（如 1-8、11-16 周）
颜色色板槽位 0-9✅槽位语义跨主题稳定（见 5.2）

设计要点：

  • 同一门课不同时段（如"高数"周一 1-2 节 + 周三 3-4 节）按 V1 简化模型录为两条课程记录（同色同名的视觉关联由用户保证），避免"课程-时段"二级模型带来的录入复杂度；远期版本可引入"同一课程多时段关联"。
  • 课程冲突检测：保存时若与已有课程在同一周次×节次区间重叠，弹提示列出冲突课程，用户可选择"仍要保存"（旁听/补课场景）或返回修改。

3.2 课程添加与编辑

入口：周视图主页右下角"+"悬浮按钮（新建）；点击课程色块 → 详情 → "编辑"（修改）。

表单交互流（新建示例）：

  1. 课程名：文本输入框（必填校验，超 20 字截断提示）
  2. 教师 / 地点：文本输入框（可选）
  3. 颜色：横向色板选择器（10 色圆点，默认按"最少使用颜色"智能预选，避免新课撞色）
  4. 星期 + 节次：七列节次网格选择器（点击起点格 → 点击终点格形成区间；支持跨节，不支持跨天）
  5. 周次模式：四选一（全周 1-N / 单周 / 双周 / 自定义勾选）；自定义提供"1-8 周"区间快捷勾选
  6. 保存 → 冲突检测 → 落库 → 周视图即时刷新 → 全部桌面卡片 ≤5 秒同步刷新

编辑：复用同一表单，预填已有值；删除需二次确认（AlertDialog），删除后同样触发卡片同步。

4. 桌面卡片体系设计 差异化核心

本章是产品差异化的核心。设计哲学：竞品把"一张课表"放上桌面，我们把"当下与接下来的答案"放上桌面。

4.1 设计理念："聚焦当下"

学生查看课表的高频真实问题排序：

  1. "下节课是什么？在哪？还有多久？"（每天 5-10 次，课间决策）
  2. "今天还有什么课？"（每天 2-3 次，规划当日）
  3. "明天/这周课多吗？"（每天 1 次以内，粗略规划）

竞品的完整周课表卡片把三个问题全部丢给用户自行查找。SchoolCalendar 的卡片矩阵按问题优先级分层设计——问题越高频，卡片越直接：

高频问题对应卡片回答方式
下节课是什么？「下一节课」直接给出唯一答案 + 倒计时
今天还有什么课？「今日课程」当日列表 + 当前位置高亮
这周整体安排？「完整周课表」全周网格总览

4.2 卡片矩阵总览

3 类卡片 × 6 个形态（类型 × 尺寸组合）：

尺寸圆角内容密度策略

4.3 三层刷新体系

单靠任何一种刷新机制都无法同时满足"数据实时、跨天推进、分钟级体验"，故设计三层组合：

L1
主动层应用内数据变更（增删改课程/改作息/换主题/改学期）→ formProvider.updateForm 遍历推送全部实例
≤ 5 秒 · 编辑即时生效
L2
定点层form_config.json 声明 scheduleUpdateTime（每日 ≤24 个时间点，取作息表中全部课程开始/结束时刻的并集）
对齐作息边界 · 跨天推进
L3
自治层卡片内 TextClock.onDateChange 回调（分钟级，API 11+ 卡片内可用）——倒计时更新、高亮迁移、今日↔明日视角切换
≤ 1 分钟 · 零配额消耗

配额约束下的设计纪律（已核验官方文档）：

  • 定点刷新每日最多 24 个时间点 → 默认 12 节作息的全部边界理论上限 24 个，恰好覆盖；用户自定义作息超出 24 点时，取"课程实际占用节次"的边界并集（未被任何课程占用的节次边界不设点），由 L3 层兜底。
  • 定时刷新（updateDuration）每卡每日 50 次配额 → 本产品不依赖定时刷新，避免无效配额消耗。
  • L3 层零配额消耗：TextClock 回调在卡片渲染进程内完成，不触发 updateForm。

4.4 卡片数据自治架构

核心思想：与其让应用每分钟告诉卡片"现在该显示什么"，不如把"推演规则所需的全部上下文"一次性交给卡片，卡片自己每分钟算出"现在该显示什么"。

数据包（WidgetData）内容：

数据用途
学期基准（开学日期/总周数/当前周）判断学期状态、单双周
作息模板（各节起止时间）当前节次定位、倒计时计算
目标日课程集（今日 + 明日 + 前瞻日）下一节课推算、今日列表渲染
主题色值包（当前深浅色变体）全部视觉渲染
空态标记引导态渲染

数据流：

[应用/卡片Extension 组装]
        │  ①课程集+作息+学期+主题 → WidgetData（全量上下文）
        ▼
[卡片实例 收到数据] ──────────────┐
        │ ②解析入本地 @State        │ L1 主动推送（数据变更 ≤5s）
        ▼                          │ L2 定点推送（作息边界）
[TextClock 每分钟回调]              │
        │ ③本地重算：               │
        │   当前节次/下一节课/       │
        │   剩余分钟/高亮位置/       │
        │   今日↔明日视角            │
        ▼                          │
[卡片渲染更新（零 IPC）] ◄──────────┘

收益：

  • 分钟级体验与系统配额解耦（L3 零消耗）。
  • 应用被杀进程后，卡片仍能自治运转最长一个"数据包有效期"（到下一个 L2 定点刷新点）。
  • 同一份 WidgetData 结构服务全部 6 形态卡片，按 widgetType 取用所需字段。

课程颜色槽位语义：colorIndex 槽位（0-9）在所有主题下保持语义稳定——用户为"高数"选了槽位 3（绿系），无论切换到哪套主题，高数始终是"那门绿课"（色值随主题微调，色系不变）。这样换肤不破坏用户已建立的"颜色↔课程"心智。

深色模式课程色：每套主题的深色变体对 coursePalette 单独调校（降饱和、提亮度），避免亮色刺眼或暗色不可见。

5.3 换肤机制

用户在主题页选择新主题
        │
        ├─→ ① Preferences 更新 currentThemeId（持久化）
        │
        └─→ ② ThemeService 读取新主题 → WidgetRefreshService
                │
                └─→ ③ 遍历全部卡片实例 formProvider.updateForm
                        （WidgetData 携带新主题色值包）
                        │
                        └─→ ④ 全部卡片 ≤5 秒呈现新主题
  • 应用内：主题切换即时生效（当前页面无刷新感知，全局色值来自统一主题状态）。
  • 卡片：色值作为数据下发，卡片渲染零硬编码色——新增主题 = 新增一条主题定义数据，零代码改动。
  • 卡片深浅色：数据包按"卡片添加时刻的系统深浅色"携带对应变体；系统深浅色切换后，卡片在下一次任意层刷新时自动切换变体。

  • 主题卡片网格：每套主题以"迷你课表预览"呈现（2×2 卡片 mock + 应用首页缩略同色系），所见即所得。
  • 当前主题高亮标注；点击即切换（无需确认，切换成本极低鼓励尝试）。
  • 页面内嵌 FormMenu 组件（API 18+）：长按任意预览卡片可"添加到桌面"，引导用户在选完主题后顺手把卡片放上桌面。

6. 系统日历同步与课前提醒

让学生不依赖本应用后台也能收到上课提醒——由系统日历完成提醒，应用只负责写入与维护。

6.1 功能设计

功能点设计
同步开关设置页"同步到系统日历"开关（默认关闭）
日历账户开启时创建应用专属日历账户（如"SchoolCalendar 课表"），与用户个人日历隔离，互不污染
课前提醒日程自带提醒，提前量可配置：5 / 10 / 15 / 30 分钟（默认 15）
增量维护课程增删改 / 作息修改 / 提醒提前量变更后，用户再次进入同步页或手动点"立即同步"时，全量重建本账户日程（先清后写）
关闭同步删除整个专属日历账户及其全部日程，课表数据不受影响

6.2 课程 → 日历日程映射规则

课表概念日历日程字段
一门课程（某周次模式下）一条重复日程
开学日期 + 周次模式RRULE 周重复 + 按"周次展开"生成各次发生时间
单双周 / 自定义周次展开为具体日期集合（不满足 RRULE 规则的日期以 EXDATE 剔除）
上课时间（作息模板）日程开始时间（下课时间 = 开始 + 课时分钟，日程时长仅示意）
课名 / 教师 / 地点日程标题"课名 · 地点" / 备注"教师：XXX"
课前提醒提前量日程提醒时间 = 开始时间 − 提前量
为什么全量重建而非逐条 diff：课程数据量小（≤40 门次 → 数百个日程实例），全量重建耗时可控（秒级）；换取实现简单与强一致——不存在"日历里残留已删课程"的脏数据状态。此为已确认的架构决策（plan.md D6）。

6.3 权限与体验设计

  • 权限：ohos.permission.READ_CALENDAR + ohos.permission.WRITE_CALENDAR，运行时按需申请——仅在用户首次打开同步开关时弹窗，未开启同步的用户全程无感知。
  • 拒绝后的引导：权限被拒 → 非阻断提示"开启日历权限后才能同步课表"，提供"前往设置"入口；同步功能保持关闭态，其余功能不受影响。
  • 系统日历侧体验：学生在系统日历 App 中看到专属账户的课表周视图，获得系统级提醒通知（锁屏/通知中心/日历 App 内），与本应用提醒体验一致。
  • 选择 Calendar Kit 而非代理提醒的原因：代理提醒（reminderAgentManager）需邮件申请权限且仅对工具类应用开放，官方 FAQ 明确推荐 Calendar Kit 日程提醒作为替代（已核验）；同时日历日程对学生还有"在日历中直接查看"的附加价值。

核心推导逻辑（不落库，实时计算，单一数据源避免状态不同步）：

  • 当前教学周 = ⌊(今天 − 开学日期) / 7 天⌋ + 1；边界：未开学 / 已结束两态
  • 某日有效课程集 = 按 (dayOfWeek 匹配) ∧ (周次模式含当前周) 过滤
  • 下一节课推算 = 定位当前时刻所在节次 → 当日有效课程集中寻找 startSection ≥ 当前节次的最近候选 → 无则逐日前瞻（≤14 天）
  • 卡片视角状态机 = 今日未开始 → 进行中 → 已结束 → 明日/前瞻，TextClock 分钟回调驱动迁移（详见 4.5/4.6）
